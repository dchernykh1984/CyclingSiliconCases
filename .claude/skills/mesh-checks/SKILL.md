# Как мерить сетку

Правило проекта: **всё, что должно поместиться, посчитано и закреплено
тестом.** Рендер — вторая проверка, а не первая. На картинке надпись,
уехавшая за кромку на полмиллиметра, неотличима от лежащей впритык, а
элемент, оказавшийся в вырезе, выглядит нормально стоящим на детали.

Весь инструмент — `src/cycling_cases/mesh.py`, один numpy, без лишних
зависимостей. Поверх него лежит `panel.py` — замер стенки сеткой лучей
и надпись, положенная по этому замеру.

## Что лежит в файле

```python
from cycling_cases.mesh import read_stl, parts, health

triangles = read_stl(path)
for part in parts(triangles):  # тела по убыванию размера
    print(part.describe(), health(part.triangles))
```

Скачанная модель сплошь и рядом оказывается **целой раскладкой на стол**:
чехол, вынос, хомуты в одном файле. Первое, что нужно знать перед правкой,
— из скольких тел она состоит и какое из них нужное. То же самое из
командной строки: `cycling-cases inspect <файл>`.

## Замкнутость: дырка и самокасание — разные беды

`edge_counts` считает, скольким граням принадлежит каждое ребро:

- **все по два** — сетка замкнута, булевы операции дадут честный результат;
- **есть по одному** — дырка. Резать такую сетку нельзя, результат будет
  мусором; её надо чинить до всего остального;
- **есть по четыре** — деталь сама себя касается. Manifold такое
  обычно переваривает, но помнить стоит: именно в этих местах вылезают
  странные артефакты после вычитания.

У чехла 840 ровно четыре ребра по четыре грани — это нормально
и зафиксировано тестом. Если там появятся рёбра по одному, значит файл
подменили.

## Сечения: единственный способ увидеть невидимое

```python
from cycling_cases.mesh import section, outline_points

segments = section(triangles, z=10.0)  # контур на высоте 10 мм
```

Сечением меряют то, чего снаружи не видно: толщину стенки, ширину полости
под велокомпьютер, зазор между гравировкой и вырезом. Полость чехла — это
внутренний контур сечения; её форма по высоте и есть форма велокомпьютера.

## Отступы: расстояние плюс «внутри ли»

```python
from cycling_cases.mesh import box_probes, clearance

probes = box_probes(centre=(0, -20), width=28.4, height=9.5, angle=0)
gap = clearance(probes, segments)
assert gap > 2.0, f"до кромки всего {gap:.2f} мм"
```

- `box_probes` даёт **девять точек**: углы, середины сторон и центр. Одних
  углов мало — кромка бывает волнистой и заходит в середину стороны.
  Если блок повёрнут вдоль детали, `angle` поворачивает и габарит.
- `clearance` возвращает **отрицательное** число, если хоть одна точка вне
  материала. Без этой проверки «отступ» врёт: точка посреди выреза стоит
  далеко от всех кромок.

Ровно на этой дыре в проверке в соседнем проекте логотип уехал в отверстие
детали и уехал бы в печать: расстояние до кромки было приличное, а материала
под ним не было.

## Разбор раскладки на тела

```bash

```

Кладёт по STL на тело. Дальше нужное тело импортируют в свою модель или

## Как это попадает в тесты

Каждая проверка — это тест с внятным сообщением и цифрой, а не «ассерт
ради ассерта»:

```python
def test_engraving_keeps_clear_of_the_cutout() -> None:
    gap = clearance(box_probes(...), section(read_stl(SOURCE), z=2.0))
    assert gap > 2.0, f"надпись подходит к вырезу на {gap:.2f} мм"
```

Верхняя граница тоже полезна: если запас вырос до нескольких миллиметров,
значит надпись можно было сделать крупнее, и об этом стоит знать.

Приёмка исходников (`tests/test_sources.py`) устроена так же: число тел,
габариты и замкнутость записаны цифрами. Подменили файл — тест скажет,
что именно изменилось.

## Лучи: толщина стенки и где в ней дырка

`ray_distances(triangles, origins, direction)` возвращает расстояние до
ближайшей грани вдоль луча (или `inf`, если промах). Мёллер—Трумбор на
numpy, без ускоряющих структур: тысяча лучей по десяти тысячам
треугольников считается за доли секунды.

Из него собирается почти всё, что нужно знать про стенку:

```python
# первая грань — наружная поверхность, вторая — внутренняя
outer = ray_distances(mesh, start[None, :], -normal)[0]
inner = ray_distances(mesh, (start - normal * (outer + 1e-4))[None, :], -normal)[0]
thickness = inner            # толщина стенки в этой точке
```

Три приёма, которые окупились:

- **Луч должен стартовать заведомо снаружи детали.** Иначе он увидит её
  изнанку, и замер молча окажется с другой стороны стенки. `panel.measure`
  считает дальность старта по габариту сетки, а не берёт константу.
- **Сквозное окно отличается от стенки длиной пробега.** Через окно луч
  пролетает деталь насквозь и утыкается в противоположную стенку — в
  тестах это порог «больше 280 мм».
- **Толщину стенки по всей длине стоит промерить, даже когда не просят.**
  Именно так у чехла 840 нашлась разметка кнопок: карманы, где автор
  утончил стенку с 1.75 до 0.75 мм.

## Площадка на стенке

```python
area = panel.measure(mesh, axis=1, sign=1, origin=(0, 0, 17.2),
                     u_range=(-17.8, 17.8), v_range=(-2.6, 2.6))
area.misses        # узлы, не попавшие в материал: не ноль — надпись вылезла
area.relief_span   # насколько поверхность уходит вглубь по площадке
area.tilt          # наибольший наклон поверхности, градусы
```

Дальше `area.emboss(line, relief)` возвращает надпись, уже лежащую по
поверхности. Проверять результат надо замером готовой детали: снять
площадку до и после и посмотреть на разницу — она должна быть ровной.
