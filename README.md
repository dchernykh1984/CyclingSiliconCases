# CyclingSiliconCases

Чехлы для велокомпьютеров Garmin. Исходные модели скачаны готовыми, лежат
в [input_data/](input_data/) и правятся кодом поверх них. Готовые STL
собирает CI и прикладывает к релизу — в репозитории их нет.

Python 3.11–3.13, uv, numpy, manifold3d, fontTools. Внешних программ
ставить не нужно: булевы операции считает manifold3d (тот же движок, что
внутри современного OpenSCAD, только как библиотека), картинки рисует свой
растеризатор, шрифт надписи лежит в репозитории.

## Быстрый старт

```bash
make install          # зависимости (uv) и хуки pre-commit
make test             # pytest
make build            # STL в ./dist
make preview          # PNG в ./preview
make inspect          # из каких тел состоят исходники
```

## Что в релизе

| Файл | Прибор | Что сделано |
| --- | --- | --- |
| `garmin-830.stl` | Edge 830 | выпуклая надпись **UBT 8 YEARS** на передней стенке, губы удержания по бокам и спереди |
| `garmin-840.stl` | Edge 840 | только чехол из раскладки, окна под все кнопки, выпуклая надпись **UBT 8 YEARS** на носу |

Ориентация у обеих моделей одна: Z — от спинки к экрану, **+Y — вперёд по
ходу движения** (передняя стенка, там надпись), −Y — к велосипедисту (там
кнопки нижнего торца), −X — левый бок прибора, если смотреть на экран.

### Надпись

Надпись **выпуклая**, высотой 0.8 мм. Под TPU это единственный разумный
вариант: гравировку глубиной в полмиллиметра слайсер на наружной стенке
затирает периметром, а наружу буква растёт свободно. Шрифт — Roboto Black;
при высоте прописной 4 мм стойка буквы выходит 0.92 мм, то есть два
периметра сопла 0.4 мм.

Ни одна стенка чехла не плоская, поэтому надпись кладётся **по поверхности**:
стенка сначала измеряется лучами, потом плитка с буквами гнётся по замеру.
Высота рельефа получается одинаковой по всей строке — 0.78…0.81 мм на 830 и
0.75…0.80 мм на 840, где нос представляет собой скруглённый гребень. Плоская
плитка на том же месте в середине торчала бы на 0.8 мм, а по краям тонула на
два-три миллиметра.

### Кнопки

У Edge 830 три кнопки: питание на левом боку, lap и start/stop на нижнем
торце. Исходный чехол открывает все три — окно 15 × 9 мм слева и окно
44 × 10 мм по всему заднему торцу. Резать нечего, геометрия окон не тронута.

У Edge 840 кнопок семь: питание, вверх и вниз слева, выбор и назад справа,
lap и start/stop на нижнем торце. Точных координат нет ни в мануале, ни в
обзорах — но их знал автор исходника: в полости чехла размечены карманы, где
стенка утончена с 1.75 до 0.75 мм. Слева таких карманов два (50.5…78.0 мм
под пару «вверх/вниз» и 83.5…98.0 мм под питание), справа тоже два
(50.5…65.0 и 83.5…98.0) — три кнопки слева и две справа, ровно как у
прибора. Окна прорезаны **по этим карманам**, так что между ними остаются
рёбра исходника в полную толщину: 6.5 мм до первого окна, 5.5 мм между
окнами слева, 18.5 мм справа и 9 мм до носа. Плюс окно 36 × 9 мм в заднем
торце под lap и start/stop — там была сплошная стенка 4.5 мм.

Мембрана 0.75 мм в TPU продавливается пальцем, но полагаться на неё не
стоит: именно тонкая стенка рвётся первой, и цепляются как раз за неё.

### Посадка

Чехол 830 держался в основном креплением Garmin: загиб, удерживающий прибор
за лицевую рамку, был только на заднем торце. Добавлены такие же губы по
двум бокам и спереди — валик с наклонной нижней гранью (34–45°, печатается
без поддержек), заходящий на рамку на 0.8 мм. По ширине полость 50.6 мм при
приборе 50 мм, так что две губы оставляют натяг 1.0 мм. Над кромкой чехла
губы не поднимаются — это проверено тестом.

Чехол 840 — бампер-рамка: она открыта и сверху, и снизу. Так задумано в
исходнике, и иначе нельзя: снизу к прибору подходит крепление Garmin, сверху
остаётся экран. Держит прибор верхняя губа рамки, она прорезку окон пережила.

## Что где лежит

| Путь | Что там |
| --- | --- |
| `input_data/` | исходные модели, скачанные готовыми; их не пересобрать, это исходный код |
| `src/cycling_cases/recipes.py` | все правки и все числа с объяснением, откуда они взялись |
| `src/cycling_cases/cases.py` | каталог: какой исходник каким рецептом правится |
| `src/cycling_cases/mesh.py` | измерительный инструмент: тела, лучи, сечения, отступы |
| `src/cycling_cases/panel.py` | замер стенки и надпись по измеренной поверхности |
| `src/cycling_cases/lettering.py` | буквы из TTF в плоские контуры |
| `src/cycling_cases/solid.py` | мост к manifold3d и примитивы правок |
| `src/cycling_cases/preview.py` | растеризатор для картинок |
| `tests/` | приёмка исходников и замеры по готовым деталям |

```bash
uv run cycling-cases list                    # что за чехлы и что с ними
uv run cycling-cases inspect Garmin840.stl   # тела, размеры, замкнутость
uv run cycling-cases split Garmin840.stl     # разложить раскладку по телам
uv run cycling-cases build --out dist        # собрать всё
uv run cycling-cases preview --out preview   # отрендерить, чтобы посмотреть
```

## Как добавить ещё один чехол

Чехлы между собой не связаны: общие у них только утилиты — чтение сетки,
замеры, булевы операции и надписи. Добавление нового — четыре шага:

1. положить скачанный STL в `input_data/` и записать в
   [input_data/README.md](input_data/README.md), откуда модель и на каких
   условиях;
2. посмотреть, что в нём: `uv run cycling-cases inspect <файл>`;
3. написать рецепт в `recipes.py` — функция берёт сетку и возвращает тело;
4. дописать одну запись в `CASES` (`src/cycling_cases/cases.py`).

Тест `test_every_source_is_registered` не даст забыть четвёртый шаг.

## Правила, которые не обсуждаются

- **В репозитории только код и исходники.** Собранные STL и превью не
  коммитятся: их делает CI и кладёт в релиз.
- **Геометрия проверяется расчётом, а не на глаз.** Всё, что должно
  поместиться на деталь, считается в `tests/` по готовой детали. Рендер —
  вторая проверка, а не первая.
- **Коммит — одна строка** в стиле conventional commits: от типа зависит
  версия, которую поставит release-please.
- **Чужие формы не переделываем молча.** Откуда взялась модель и на каких
  условиях — в [input_data/README.md](input_data/README.md); что именно мы
  с ней делаем и из каких чисел это следует — в `recipes.py`.

Подробности для тех, кто правит модели, — в `.claude/skills/`.
