# CyclingSiliconCases

Чехлы для велокомпьютеров Garmin. Исходные модели скачаны готовыми, лежат
в [input_data/](input_data/) и правятся моделями OpenSCAD поверх них. Готовые
STL собирает CI и прикладывает к релизу — в репозитории их нет.

Python 3.11–3.13, uv, numpy, OpenSCAD.

## Быстрый старт

```bash
make install          # зависимости (uv) и хуки pre-commit
make test             # pytest
make build            # STL в ./dist
make preview          # PNG в ./preview (нужен openscad)
make inspect          # из каких тел состоят исходники
```

## Что где лежит

| Путь | Что там |
| --- | --- |
| `input_data/` | исходные модели, скачанные готовыми; их не пересобрать, это исходный код |
| `src/cycling_cases/cases.py` | каталог чехлов: исходник, наша модель поверх него, что уходит в релиз |
| `src/cycling_cases/assets/models/` | наши модели OpenSCAD — правки к чужим сеткам |
| `src/cycling_cases/mesh.py` | измерительный инструмент: тела, сечения, отступы |
| `src/cycling_cases/openscad.py` | запуск OpenSCAD |
| `tests/` | приёмка исходников и проверки геометрии |

## Как это устроено

Пока у чехла нет своей модели, он уходит в сборку **копией исходника**, байт
в байт. Первый релиз поэтому отдаёт ровно то, что лежит в `input_data`.
Как только у чехла появляется модель в `assets/models`, сборка начинает
резать STL из неё, и разница между релизами видна по файлу.

```bash
uv run cycling-cases list                    # что за чехлы и что с ними
uv run cycling-cases inspect Garmin840.stl   # тела, размеры, замкнутость
uv run cycling-cases split Garmin840.stl     # разложить раскладку по телам
uv run cycling-cases build --out dist        # собрать всё
uv run cycling-cases preview --out preview   # отрендерить, чтобы посмотреть
```

## Как добавить ещё один чехол

Чехлы между собой не связаны: общие у них только утилиты — чтение сетки,
замеры и запуск OpenSCAD. Добавление нового — три шага:

1. положить скачанный STL в `input_data/`;
2. дописать одну запись в `CASES` (`src/cycling_cases/cases.py`) — имя,
   велокомпьютер, имя файла;
3. записать в `input_data/README.md`, откуда модель и на каких условиях.

Тест `test_every_source_is_registered` не даст забыть второй шаг, а
`uv run cycling-cases inspect <файл>` сразу покажет, из скольких тел
состоит новый исходник и замкнут ли он.

Правки к чехлу живут в своей модели `assets/models/<имя>.scad` и ничего
не знают про соседние: каждая импортирует свой исходник и делает с ним
своё.

## Правила, которые не обсуждаются

- **В репозитории только код и исходники.** Собранные STL и превью не
  коммитятся: их делает CI и кладёт в релиз.
- **Геометрия проверяется расчётом, а не на глаз.** Всё, что должно
  поместиться на деталь, считается в `tests/`. Рендер — вторая проверка,
  а не первая.
- **Коммит — одна строка** в стиле conventional commits: от типа зависит
  версия, которую поставит release-please.
- **Чужие формы не переделываем молча.** Откуда взялась модель и на каких
  условиях — в [input_data/README.md](input_data/README.md).

Подробности для тех, кто правит модели, — в `.claude/skills/`.
